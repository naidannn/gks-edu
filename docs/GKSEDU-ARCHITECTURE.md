# GKSEDU-ARCHITECTURE.md

## Хэл сургалтын төвийн модуль (Үе шат 2.5) — MIRAE Smart Education

> Энэ баримт нь `gksedu.md`-ийн §4.4 болон §21 "Үе шат 2.5"-д иш татагдсан, өмнө нь байхгүй байсан техникийн тодорхойлолт юм. Ерөнхий системийн архитектур (хэрэглэгчийн эрх, мэдэгдэл, тайлангийн самбар зэрэг) `gksedu.md`-д тодорхойлогдсныг энд давтахгүй — зөвхөн энэ модульд шинээр нэмэгдэх өгөгдлийн загвар, төлөв, урсгалыг тодорхойлно.

---

## 1. Модулийн зорилго ба хамрах хүрээ

MIRAE Smart Education брэндийн дор ажилладаг Солонгос болон Англи хэлний танхимын болон онлайн сургалтын үйл ажиллагааг удирдах модуль. Энэ нь зуучлалын гол процессоос (гэрээ → материал → виз) **тусдаа домэйн** боловч:

- Ижил байгууллага (§1.1 — GKS EDU GROUP ХХК)
- Ижил хэрэглэгчийн бүртгэл, эрхийн систем (§18)
- Ижил CRM/харилцагчийн сан руу lead дамжуулна (§4.4, §5.2)

ашигладаг тул тусад нь модуль болгож, гэхдээ гол системтэй нэг өгөгдлийн санд (харилцагчийн бүртгэл дундын) байршуулна.

Хамрах хүрээнд ОРОХГҮЙ зүйлс: гэрээ, QPay төлбөр, материал бүрдүүлэлт, виз — эдгээр нь зөвхөн зуучлалын гол процесст хамаарна (§4.1–§4.3).

## 2. Үндсэн харьцаа (танхим ба онлайн)

`gksedu.md` §4.4 болон AI-MEDEELLIIN-SAN баримтад дурдсан одоогийн (гараар ажилладаг) бүтцийг систем дараах тогтмол лимит болгон бус, **тохируулж болох админ тохиргоо** болгон загварчилна (учир нь ангийн тоо, цаг, төлбөр цаг хугацаанд өөрчлөгдөж болно):

| | Танхимын сургалт | Онлайн сургалт |
|---|---|---|
| Ангийн тоо (өнөөдрийн байдлаар) | 6 | 4 |
| Нэг ангийн дүүргэлтийн дээд хязгаар | 16 | 10 |
| Өдрийн ээлж | 10:00–13:00 / 15:00–18:00 / 18:00–21:00 | 17:00–19:00 / 19:00–21:00 |
| Хичээллэх өдрийн хослол | Даваа-Лхагва-Баасан **эсвэл** Мягмар-Пүрэв-Бямба | Даваа-Лхагва-Баасан **эсвэл** Мягмар-Пүрэв-Бямба |
| Долоо хоногийн давтамж | 3 удаа × 3 цаг | 3 удаа |
| Төлбөр (одоогийн жишээ) | 1 сар 350,000₮ / 3 сар 1,000,000₮ | 1 сар 200,000₮ |

Эдгээр тоонууд админ тохиргооны утга гэдгийг тодотгож, хатуу кодлохгүй.

## 3. Өгөгдлийн загвар (энтити)

### 3.1. Хэлний хөтөлбөр (`LanguageProgram`)
- Хэл: Солонгос / Англи
- Түвшин: Анхан / Дунд / Гүнзгий / TOPIK бэлтгэл / IELTS бэлтгэл / Ярианы анги
- Тайлбар, зорилтот бүлэг (ЕБС 5–12, оюутан, элсэгч, насанд хүрэгч)

### 3.2. Анги (`ClassGroup`)
- Хамаарах `LanguageProgram`
- Хэлбэр: Танхим / Онлайн
- Багш (`Teacher`)
- Хуваарь: өдрүүд (жишээ: Даваа/Лхагва/Баасан), эхлэх–дуусах цаг
- Дүүргэлтийн дээд хязгаар, одоогийн бүртгэлтэй тоо
- Эхлэх / дуусах огноо (улирал)
- **Ангийн төлөв:** `Элсэлт нээлттэй` → `Дүүрсэн` → `Идэвхтэй` → `Дууссан` (мөн `Цуцлагдсан`)

### 3.3. Суралцагчийн бүртгэл (`Enrollment`)
- Суралцагч (гол системийн хэрэглэгчийн бүртгэлтэй холбогдоно — §18.2)
- Хамаарах `ClassGroup`
- Элссэн огноо
- **Бүртгэлийн төлөв:** `Идэвхтэй` → `Түр зогссон` → `Гарсан` / `Төгссөн`
- Зуучлалын сонирхолтой эсэх тэмдэглэгээ (`potential_brokerage_lead: true/false`) — доор §5-г үзнэ үү

### 3.4. Ирц (`Attendance`)
- Хамаарах `Enrollment`
- Хичээлийн огноо
- **Ирцийн төлөв:** `Ирсэн` / `Тасалсан` / `Чөлөөтэй (мэдэгдсэн)` / `Оройтсон`
- Тэмдэглэл (багшийн бичих сонголт)

### 3.5. Төлбөрийн мөчлөг (`TuitionCycle`)
- Хамаарах `Enrollment`
- Мөчлөгийн төрөл: 1 сар / 3 сар
- Дүн, эхлэх–дуусах огноо
- **Төлөвийн урсгал:** `Хүлээгдэж буй` → `Төлөгдсөн` / `Хугацаа болсон` → `Хоцорсон` (мэдэгдэл идэвхжинэ — §16-тай ижил механизм) → `Цуцлагдсан`

### 3.6. Багш (`Teacher`)
- Заадаг хэл, түвшин
- Хуваарьт байгаа ангиуд (`ClassGroup[]`)
- Долоо хоногийн ачааллын тооцоо (тайланд ашиглагдана)

### 3.7. Ахицын үнэлгээ (`ProgressNote`) — сонголтоор
- Хамаарах `Enrollment`
- Огноо, багшийн үнэлгээ/тэмдэглэл (жишээ: TOPIK дадлага оноо)

## 4. Элсэлт → Хичээллэлт → Дуусгавар урсгал

1. Сонирхогч хэрэглэгч (зочин эсвэл бүртгэлтэй) хөтөлбөр, ангиа сонгоно.
2. Ресепшн/админ ажилтан суралцагчийг `Enrollment`-д бүртгэж, эхний `TuitionCycle`-ийг үүсгэнэ.
3. Төлбөр баталгаажсаны дараа `Enrollment` идэвхжинэ, анги дүүрсэн эсэхийг систем автоматаар шалгаж `ClassGroup` төлөвийг шинэчилнэ.
4. Хичээл тутамд багш `Attendance` бүртгэнэ.
5. Мөчлөг дуусахад дараагийн `TuitionCycle` автоматаар үүсэж, төлбөрийн сануулга идэвхжинэ (§16-ийн мэдэгдлийн механизмтай ижил).
6. Хөтөлбөр дуусах, эсвэл суралцагч гарахад `Enrollment` → `Төгссөн`/`Гарсан` болно.

---

## 5. Зуучлалын CRM руу lead дамжуулах холболт

`gksedu.md` §4.4-т дурдсанчлан хэлний сургалтын суралцагч нь ирээдүйн зуучлалын үйлчлүүлэгч байх магадлал өндөр (жишээ: TOPIK бэлтгэлд сурч буй суралцагч БНСУ-д суралцах сонирхолтой). Тиймээс:

- Ажилтан (эсвэл AI чат туслах, §13) тухайн суралцагчийг **"Зуучлалын сонирхолтой"** гэж тэмдэглэвэл, `Enrollment.potential_brokerage_lead = true` болж, гол системийн Харилцагчийн бүртгэл (§5.2)-д автоматаар боломжит харилцагч (lead) үүснэ — давхар мэдээлэл оруулах шаардлагагүй.
- Энэ lead нь §5.2-ын "Анх холбогдсон суваг" талбарт `"Хэлний сургалтын төв"` гэж бүртгэгдэнэ, борлуулалтын ажилтанд хуваарилагдана.

---

## 6. Тайлан (энэ модульд нэмэлтээр)

- Ангийн дүүргэлтийн хувь (нийт багтаамж vs бүртгэлтэй тоо)
- Ирцийн дундаж хувь (анги тус бүрээр, суралцагч тус бүрээр)
- Багшийн долоо хоногийн ачаалал
- Сургалтын төлбөрийн орлого (сар тутам, ангиар)
- Хугацаа хэтэрсэн төлбөртэй суралцагчийн жагсаалт
- Хэлний сургалтаас зуучлалын CRM руу шилжсэн lead-ийн тоо, хөрвөлтийн хувь

---

## 7. Тодруулга шаардлагатай зүйлс (энэ модульд хамаарах)

- Ангийн тоо (6 танхим / 4 онлайн), дүүргэлтийн лимит нь **өнөөгийн** байдал уу, эсвэл системд хатуу тохируулга болгож оруулах уу?
- Trial/танилцах хичээл (chёлөөт нэг удаагийн хичээл) байдаг эсэх — одоогийн баримт бичигт дурдаагүй.
- Хичээл цуцлагдах/хойшлогдох тохиолдолд (багш өвдсөн гэх мэт) мэдэгдэл, нөхөн хичээлийн урсгал тодорхойгүй.
- Ангиас ангид шилжих (жишээ: Анхан → Дунд) шаардлага, шалгалтын босго тодорхойгүй.
